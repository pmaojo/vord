## 2024-07-25 - Avoid String Allocation in propagate_bindings Hot Loop
**Learning:** We can bypass unconditional `.entry(key.to_string()).or_default()` in tight fixed-point iteration loops over `HashMap<String, T>`. Even if the key is typically borrowed, `.entry()` always takes ownership, allocating even if the key is already present.
**Action:** Use a `.get_mut(borrowed_key)` followed by a `.insert(borrowed_key.to_string(), ...)` fallback when dealing with string-keyed HashMaps inside hot loops, keeping allocations strictly proportional to the number of *unique* elements, rather than the number of iterations.
## 2024-07-30 - Eliminate Heap Allocations in Tarjan SCC Algorithm
**Learning:** In standard graph algorithms like Tarjan's SCC over `BTreeMap<String, Vec<String>>`, extracting `.keys().cloned().collect::<Vec<_>>()` and `.get(&v).cloned().unwrap_or_default()` forces unnecessary full-graph and full-adjacency-list copies. By leveraging the lifetime of the borrowed graph `&'g BTreeMap`, we can iterate over the keys directly without collecting or cloning strings unless a graph node is newly discovered and must be tracked.
**Action:** Replace `self.adjacency.keys().cloned().collect::<Vec<_>>()` with direct iteration over `self.adjacency.keys()` and iterate directly on the `&Vec<String>` returned by `self.adjacency.get(&v)`, passing string copies only into hash structures requiring ownership.
